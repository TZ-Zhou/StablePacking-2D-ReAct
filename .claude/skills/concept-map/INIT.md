# init：對陌生專案一次跑完

觸發：`/concept-map:init [專案路徑]`，或 `/concept-map init`。
使用者下這個指令就是同意「一路做完，不中途問」。草稿的可信度靠「待確認」標記與最後的回報，不靠中途提問。

## 不做的事

- 不 commit、不 push、不發佈 Artifact。
- 不改專案原始碼，不改既有文件的內容（只在下面列的兩個檔各加一行）。
- 地圖已存在就停：回報位置，建議 `/concept-map 對一下現況`；使用者明說「重建」才覆蓋，且先把舊檔複製成同名 `.bak`。

## 步驟（依序，全部做完才回報）

1. **定專案根**：給了路徑就用它；否則 `git rev-parse --show-toplevel`，不是 git 就用目前目錄。
2. **找既有地圖**：做 SKILL.md 的步驟 0.1、0.2。找到就依上面的規則停。
3. **盤點**：`python .claude/skills/concept-map/scripts/survey.py <專案根>`。輸出已含清單檔、README 開頭、文件、入口檔、頂層目錄與代表檔。
4. **補讀，總量上限約 25 個檔**：
   - README 與 `docs/` 的總覽類文件（不全讀）。
   - 盤點看不出職責的頂層目錄，各讀最多 3 個代表檔的開頭。
   - 超過 2000 檔或 8 個以上程式目錄的專案：先把目錄歸成 5–9 組再讀，不逐目錄讀。
   - 不讀測試、資料檔、產物、第三方程式碼。
5. **決定 L1 切法**，二選一，選最貼近這個專案的：
   - 流程型（資料或請求依序經過幾個階段）：盒子是階段，照先後排。
   - 分層型（函式庫、框架、服務）：盒子是模組或層，由內到外排。
   盒子 5–9 個；ID 用 A、B、C…（不超過 3 字元）；名稱用專案自己的詞。
6. **起草地圖**，格式照 `template.md`：
   - 檔頭「最後確認：<今天>（草稿：init 自動起草，未經人工確認）」。
   - §1 L0：輸入、輸出、不可違反的邊界（只寫文件或程式明確表達的）。
   - §2 L1：一張 mermaid（圖的畫法見 SKILL.md；一種顏色一種角色，最多 4 種）。
   - §3 每盒一張表：Input、Output、保證、內部、程式。
   - **只寫讀得到的事實。** 讀不到的（設計意圖、為什麼這樣切、對外保證）一律寫「待確認：…」並說明你在猜什麼，不編造。
   - 「程式」欄只放確實存在的路徑；數字、公式、欄位清單不寫，只指向出處。
   - 不寫 L2；使用者之後點名才展開。
7. **存檔**：專案有 `docs/` 就存 `docs/architecture-map.md`，否則存專案根的 `ARCHITECTURE-MAP.md`。語言跟使用者對話一致。
8. **build**：`python .claude/skills/concept-map/scripts/build.py --root <專案根> --map <地圖>`。
   - 警告是自己草稿造成的（路徑不存在、節點沒有盒子、缺欄）就修，最多重跑 2 次。
   - 「未登記」的目錄或檔案：職責明顯就登記到最近的盒子；不明顯就留著，列進回報。
9. **兩處各加一行**：
   - `.gitignore` 沒有 `.claude/concept-map/` 就附加這一行（沒有 `.gitignore` 且是 git 專案就建立只含這一行的檔）。
   - 專案已有 `CLAUDE.md` 就附加 `概念地圖：<地圖相對路徑>`；沒有 `CLAUDE.md` 就不建立（地圖檔名會被步驟 0.2 找到）。
10. **開圖**：有內建瀏覽器面板就 `navigate` 開 `viewer.html`，再 `go('')`；沒有就給 `file:///` 路徑。
11. **回報**（精簡，繁體中文）：
    - 地圖與 viewer 的路徑、盒子名單（一行）。
    - 「待確認」共幾項，列最重要的 5 項。
    - build 的剩餘警告、`survey.py` 是否截斷。
    - 改了哪些既有檔（`.gitignore`、`CLAUDE.md`）。
    - 一句提醒：這是讀程式推測的草稿，盒子切法與「保證」欄請你過目；改法是說「更新地圖」或「展開 X」。
