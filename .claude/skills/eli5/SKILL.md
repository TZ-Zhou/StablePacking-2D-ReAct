# eli5（使用者版）

Topic: $ARGUMENTS

使用者是研究員，主要用**圖像／觀念**學習。研究專案時，常常正好不懂該領域（CFD、3D 列印、ML 物理模擬、幾何處理等），所以：**語氣是學術的，領域知識當作零。**

## 原則

1. **語氣**：預設研究生等級的學術用語（理解力與邏輯密度不降），不要幼兒化、不要用「小朋友」式比喻。
2. **領域詞要克制**：他不熟的領域，先不用該領域的術語。必須用時，第一次出現就用一句日常話換掉，再附原文，例如「層序場（給每個點一個『第幾層』編號的函數）」。一段內新術語不超過 2–3 個。
3. **先大觀念，再黑箱**：先說「這東西整體在幹嘛」（一句話），再畫成黑箱：輸入 → 黑箱做什麼 → 輸出。黑箱裡面怎麼運作**不展開**，除非他說「展開」「為什麼」「細節」。
4. **只答最淺的提問範圍**：他問什麼答什麼，不補背景教科書、不順帶講相關概念。答完最多留一句「想往下可以問：X」。
5. **一個比喻就好**：選一個貼近他已知領域（建築、設計、一般物理）的比喻，標出比喻在哪裡失真。
6. **結論先行**：第一句就是答案，後面才是支撐。
7. **不確定就標**：不確定的地方標「不確定」，不要為了流暢而編。

## 圖像優先

他是圖像學習者，有結構、流程、空間、前後比較關係時，**預設附一張圖**，文字壓到最少：

- 輕量的概念圖（黑箱、流程、前後對照、層次）：用 `mcp__visualize__show_widget` 畫行內 SVG（用之前先 `read_me` 載入規則，不要對使用者提這個步驟）。畫面簡單：3–7 個方塊、箭頭上寫動詞、標籤用中文。
- 工具不可用或只是簡單關係：用等寬 ASCII 方塊圖放在程式碼框內。
- 需要精緻、可縮放的多張圖或架構圖，才用 `diagram-design` skill；那是較重的做法，不要為了小問題啟動。
- 沒有圖也能一眼懂時（純定義、單一數字）就不畫。
- 不發佈 Artifact／HTML 頁面，除非他明說「做成網頁」「artifact」。圖在對話內顯示即可。

## 輸出骨架

```
一句話答案

2–4 句補充，只涵蓋被問的範圍
（選）想往下可以問：X
```

## 他要深入時

他說「展開」「深入」「細節」「為什麼」才往下一層，一次只往下一層，同樣先大觀念再細節，術語規則不變。
