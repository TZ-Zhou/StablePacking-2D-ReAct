# 文件撰寫原則 — StablePacking-2D-ReAct

## 文件只寫現況，沿革一律不寫

**所有 Markdown 文件（計畫書、技術文件、README、錯誤紀錄）一律只寫「現在成立的事實」。**

**禁止寫入文件的內容：**

- 「前一版說 X，本版更正為 Y」這類版本沿革
- 「原本寫 A，該說法作廢」這類自我更正的敘事
- 「⚠️ 本節於某日訂正」這類訂正註記
- 已被取代的數字、結論、方案，即使加了刪除線或「已作廢」標籤

**理由**　沿革註記會讓讀者必須先讀完已作廢的內容，才找得到現行結論。
同一份文件裡並存三代數字時，引用者無從判斷該用哪一個。
**版本歷史由 git 保存，那是它的工作。**

**改法**　數字或結論變了就**直接覆寫**，不留痕跡。
整份文件的骨架變了就**刪掉舊檔、寫一個新檔**，不要在舊檔裡疊加註記。
變更的理由與被取代的內容寫進 **commit message**，不寫進文件。

**唯一例外**　使用者明確要求保留歷史紀錄時才寫。

## 文件放哪

- 計畫、規格、決策、觀念與查證文件一律放 `docs/`，分類與命名見 `docs/README.md`。
- 資料夾說明寫在該資料夾的 `README.md`；agent 工作規則寫在 `.claude/`。

## 數字只有一個家

- 研究結論只寫在 `research/findings.md`；牆品質數值只在 `research/quality/<方法>/`；實驗設定（種子、arm、timeout）只在 campaign 的 `campaign.json`。其他文件只引用，不重列。
- README 只說明資料夾內容，不重述數字與結論。
- 發現文件間數字不一致，以上述來源為準並回報，不要自行挑一個改。

## 哪些文件不改

- `Tests/*/readme.md` 與根目錄 `readme.md` 的上游原文（Wang et al.）不改寫；要補充就另加段落。
