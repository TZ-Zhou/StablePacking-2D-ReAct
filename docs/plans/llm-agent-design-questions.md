# 討論：LLM agent 的架構問題

`docs/plans/simulation-to-llm-agent.md` 第二部分（分析與 LLM agent）展開之前，要先決定的架構問題。這些決定會鎖定之後要做哪些分析、要跑哪些模擬、最後怎麼比較，晚決定的代價是重跑或重寫。

每個問題依同樣的格式整理：

- **決定什麼**
- **為什麼影響大**：決定後會鎖定什麼
- **現有證據**：數字以 `research/findings.md` 為準，這裡只引用
- **選項**：優點、缺點、要多做的事
- **與其他問題的關係**
- **建議**，以及什麼證據會推翻這個建議
- **最晚何時決定**
- **需要你回答的事**

建議只是討論的起點，每一題都由使用者決定。

## 問題之間的關係

```text
Q0 研究要宣稱什麼
 ├─→ Q1 目標指標 ──────────────┬─→ Q6 標籤的定義 ─→ C 組分析（h、模型）
 ├─→ Q2 動作空間 ─┐             │
 ├─→ Q3 LLM 的角色 ┼─→ Q7 資訊邊界 ─→ D 組（給 LLM 的資訊）
 │                └─→ Q9 公平比較的預算 ─→ E 組（評估）
 └─→ Q4 保留集與驗證協定 ─→ S0（現在就要指定）
Q5 統計單位與去重 ─→ A、B、C 組的寫法
Q8 場景範圍 ─→ Q4、D 組
Q10 LLM 供應商與重現性 ─→ E 組
Q11 資料放哪、在哪台跑 ─→ A 組
```

| 最晚決定時間 | 問題 |
| --- | --- |
| S1 開跑前 | Q4（保留集），Q8（場景範圍，至少確定保留場景） |
| 開始寫 A 組工具前 | Q5、Q11 |
| C 組分析前（S2 結束前） | Q0、Q1、Q6、Q7 |
| D 組開工前（S3 結束前） | Q2、Q3 |
| E 組開工前 | Q9、Q10 |

Q0 雖然不是最早用到，但它決定 Q1–Q3 的方向，建議最先討論。

## Q0 研究要宣稱什麼

**決定什麼**　這個專案最後要證明的一句話。

**為什麼影響大**　宣稱決定了 E3 的對照組、需要哪些模擬（S4），以及什麼結果算成功。宣稱不清楚的話，做完所有分析也不知道結果是好是壞。

**現有證據**

- 濾波順序的效果小，殘差（路徑分歧）佔大部分。
- 五個當下分數對長期結果的一致率接近 50%（Temporal myopia）。
- 讓 LLM 依同樣的五個分數去推理，原則上贏不過隨機，除非它拿到新的資訊。

**選項**

| 宣稱 | 要證明什麼 | 優點 | 風險 |
| --- | --- | --- | --- |
| A 效能 | LLM agent 蓋的牆比 Paper 與其他基準好 | 最直接、最有說服力 | 用相同資訊的非 LLM 規則很可能一樣好，那就說不出 LLM 的貢獻 |
| B 知識的價值 | 給 LLM 資料轉成的知識後，決策比不給時好 | 比較容易成立；正好對應「把資料轉成 LLM 的決策依據」這個題目 | 兩者都輸給 Paper 時，貢獻很弱 |
| C 彈性與可解釋 | 效能與規則相當，但 LLM 能說明理由，也能接受自然語言的目標（例如「這面牆以穩定為優先」） | 符合 LLM 真正的長處 | 要另外評估理由是否忠實，也要設計「不同目標」的實驗 |
| D 方法 | 從模擬資料萃取 agent 知識的流程本身 | 不依賴 LLM 一定要贏 | 貢獻偏工程，要有說服力需要跨場景成立 |

**與其他問題的關係**

- 選 A：Q3 必須讓 LLM 在決策上有實權，Q9 要定嚴格的公平預算。
- 選 B：E2 的消融就是主要結果。
- 選 C：Q1 要支援多種目標，Q2 要有能反映目標差異的動作空間。

**建議**　以 B 為主要宣稱，A 為次要；C 保留為退路，但從一開始就記錄 LLM 的理由，之後才有材料。

- 理由：B 是這個專案題目的本體，而且在每個結果下都能寫出有意義的結論。只追 A，一旦 LLM 贏不過規則就沒有結論。
- 主要比較：LLM 加知識、LLM 不加知識、相同資訊的非 LLM 規則、Paper。

**會推翻建議的證據**　B3 顯示上限很小，而且 C4、C5 都找不到有預測力的訊號。這時沒有知識可以給，B 不成立，應該轉向 C 或 D。

**最晚何時決定**　S2 結束前（C 組分析要依它決定標籤與檢定）。

**已決定**　LLM 加上模擬資料轉成的知識，表現不輸 Paper（容許差距事先定好，見 Q1）；同時比較加知識與不加知識，說明知識的作用。贏過 Paper 是加分，不是必要條件。

**需要你回答**　論文或報告的主要主張是哪一個？有沒有指導教授或計畫書已經寫定的方向？

## Q1 目標指標

**決定什麼**　「牆比較好」的定義：主要指標、次要指標、指標之間怎麼取捨。

**為什麼影響大**　這是 C 組所有標籤、h 的預測對象、模型的訓練目標、E3 的主要檢定。之後再換目標，C 組要全部重算，LLM 手冊也要重寫。

**現有證據**（`TH_T80`）

- `F_LR` 與牆高幾乎無關；`F_AV` 與牆高強烈負相關。
- 因果分支中，同一次改動常讓 `F_LR` 變好但牆高變差。
- `TH_T80` 的石頭總面積只佔目標面積約 41%，`F_SF` 在這個場景只反映有沒有放完。其他場景未知。

**選項**

| 作法 | 內容 | 優點 | 缺點 |
| --- | --- | --- | --- |
| 單一加權分數 | 例如各指標標準化後相加 | 簡單，模型好訓練 | 權重沒有依據；取捨被藏起來 |
| 字典序 | 先比完成度，同分再比牆高，再比 `F_LR` | 清楚、符合直覺 | 次要指標幾乎用不到 |
| 限制加目標 | `F_LR` 不比 Paper 差超過 δ（非劣性），在此條件下讓牆高最低、完成度最高 | 穩定度是安全條件，本來就該是限制；檢定清楚 | δ 要事先定 |
| Pareto | 只報告支配關係與 hypervolume | 不需要權重 | 很難得出「誰比較好」的結論；模型難訓練 |
| 執行時由使用者指定 | 目標寫在 prompt，LLM 依目標決策 | 正是 LLM 的長處（對應 Q0 的 C） | 每個目標都要有對應的標籤與評估，工作量倍增 |

**還沒確認的事**

- **牆高在每個場景都有意義嗎？** 建牆在石頭用完或填滿 99.9% 時停止。如果某個場景的牆常常頂到框，牆高會飽和，就不能當目標。A4 要先檢查。
- **`F_SF` 在其他場景是否也只代表完成度？** 要看各場景石頭面積佔目標面積的比例。
- **`F_LR` 的雜訊有多大？** 它是左右兩側極限載重的較小值，對細節敏感。B1 會量出它的殘差佔比。

**建議**　採用「限制加目標」：

- 主要：完成度（放了幾塊）優先，再比牆高（越低越好）。
- 限制：`F_LR` 非劣性，δ 由 B1 量到的 `F_LR` 標準差決定（例如 0.5 SD）。
- 監測：`F_AV`、`F_AH`、`F_SF`，只報告，不做主要檢定。
- 跨場景合併時，每個場景先各自標準化。
- 理由：與 surface-fit 的決定一致；穩定度交給 LLC 門檻與非劣性限制，幾何交給 h，分工清楚。

**會推翻建議的證據**　A4 發現某些場景的牆高沒有意義，或 B1 顯示 `F_LR` 主要是雜訊（那它連當限制都不可靠）。

**最晚何時決定**　C 組分析之前（S2 結束前）。

**需要你回答**　研究關心的是「穩定」還是「密實」，或兩者都要？你會想讓 LLM 依不同目標建牆嗎（對應 Q0 的 C）？

**已決定**　四項指標 `F_SF`、`F_AH`、`F_AV`、`F_LR` 都納入，四項都不輸 Paper 超過 δ = 0.5 SD 才算不輸，檢定方式見 `docs/plans/simulation-to-llm-agent.md` E3。C 組的主要標籤與 h 的預測對象（surface-fit 計畫）也是這四項；牆高與完成數是次要標籤，只報告。上面的「建議」不採用。

## Q2 動作空間

**決定什麼**　LLM 每次被呼叫時能做什麼，以及什麼時候被呼叫。

**為什麼影響大**　動作空間決定 LLM 影響力的上限。選錯的話，資訊做得再好也發揮不出來。改動作空間也要改建牆程式，而且要證明既有政策的牆逐位元不變。

**現有證據**

- 每一步的可行候選中位數 14 個，但 120 種順序只能選到中位數 3 個；15.8% 的步驟只有 1 種結果。
- 選中的候選有 71.8% 是該步 LLC 最高的。
- 第 13 步以後可行姿態快速減少（12.7 → 1.9），尾盤的選擇最少，影響卻最大。
- surface-fit 計畫的評估：「只給 LLM 更多資訊而不放寬動作」不建議，因為可選結果仍只有中位數 3 個。

**選項**

| 動作 | 每次可選 | 優點 | 缺點 | 要做的事 |
| --- | --- | --- | --- | --- |
| A 每步選順序（現行） | 中位數 3 種結果 | 基礎建設全部現成（控制器、檢查、重放、GPT 牆）；與 Wang 的方法論一致 | 影響力上限低 | 無 |
| B 直接選候選 | 中位數 14 個 | 上限最高 | LLM 要比較 14 個候選，token 成本高；可能選到幾何漂亮但不穩的位置 | 改 `selection.py` 與 `build_wall.py`，證明既有牆不變 |
| C 規則先排序，LLM 從前 k 名選 | k 個（例如 3–5） | 成本與風險可控 | LLM 要有規則沒有的資訊才有意義，否則只是重複規則 | 同 B，另加排序規則 |
| D 預設順序，LLM 必要時直接指定候選 | 3 種，必要時 14 個 | 平常省成本，關鍵時有彈性 | 介面複雜；「何時該介入」本身也要學 | 同 B |
| E 策略層 | LLM 每隔幾步從少數幾種策略中選一種（例如「現在放大石」「先把頂面填平」），每種策略是一個規則 | 符合 LLM 擅長高層規劃的特性；呼叫次數少；理由容易解讀 | 策略要事先設計；策略之間的差異要夠大 | 設計並驗證策略規則 |

**呼叫時機**　每步都呼叫，或只在 C3 指出的高影響階段（預期是尾盤）呼叫。只在尾盤呼叫，成本可能降到幾分之一。

**與其他問題的關係**

- Q3：E 對應「規劃者」，C 對應「仲裁者」。
- Q7：B、C、D 需要候選的幾何資訊；E 需要剩餘石頭的資訊。
- S4b（random 控制器牆）只在選 A 時需要。

**建議**　分兩步走：

1. 現在先把 B 的基礎建設做好（surface-fit 計畫的階段 2 本來就要做），並保留 A 當對照。
2. 第一版 LLM agent 在 C 與 E 之間選一個，等 B3、C3 的結果再決定。B3 顯示上限小時選 E；C4 找到有用的 h 時選 C。

- 理由：A 的上限已有證據顯示偏低；B 對 LLM 的負擔太大，也最容易選出不穩的位置。C 與 E 都把 LLM 放在它擅長的位置。

**會推翻建議的證據**　B3 顯示「每步選順序」的上限其實很大（例如狀態樹中最好的葉子明顯優於 Paper），而且 C 組顯示可以預測。這時維持 A 最省事。

**最晚何時決定**　D 組開工前。但要不要先做 B 的基礎建設，現在就要決定。

**需要你回答**　「LLM 選濾波順序」是不是計畫書已經定死的題目？如果是，B–E 都算偏離原題，要先確認可以改。

**已決定**　題目沒有限定選順序。現在就在分支上做 B 的基礎建設，不在 pc1 的工作目錄做；pc1 維持 `factorial-v1` 直到 S3 結束才合併。第一版 agent 用 C 或 E，依 B3、C3 決定。

## Q3 LLM 的角色

**決定什麼**　LLM 在整個系統裡負責哪一段。

**為什麼影響大**　角色決定要做的評估和要證明的事。有些角色根本不需要在建牆時呼叫 LLM。

**現有證據**

- 當下分數對長期結果幾乎沒有資訊，所以 LLM 的價值必須來自新的資訊，或來自整合資訊的能力，不能來自「更會讀這五個分數」。
- 現行的 ReAct 控制器已能讀觀測、呼叫工具、選順序，並記錄理由。

**選項**

| 角色 | 建牆時呼叫 LLM | LLM 的價值在哪 | 怎麼評估 |
| --- | --- | --- | --- |
| A 線上決策者 | 每次決策 | 整合多種資訊、處理罕見情況 | E3，對照非 LLM 規則 |
| B 仲裁者 | 只在規則不確定時（例如前幾名的差距很小） | 只處理困難的情況 | 困難情況子集上的勝率 |
| C 規劃者 | 每隔幾步 | 高層規劃（對應 Q2 的 E） | E3 |
| D 離線知識萃取者 | 不呼叫 | LLM 讀分析結果，寫出規則或手冊；規則在建牆時獨立執行 | 萃取出的規則與人工設計的規則相比 |
| E 解說者 | 不影響決策 | 解釋規則為何這樣選 | 理由與實際原因是否一致 |

**值得一提的組合**

- **A 或 C 加上 D**：先讓 LLM 離線把分析結果寫成手冊（D），再讓線上的 LLM 讀這份手冊做決策。這樣「資料轉成 LLM 依據」的過程本身也交給 LLM，正好可以和人工寫的手冊比較。
- **多模態**：把牆面圖片直接給視覺模型，讓它看形狀，而不只讀數字。LLM 的空間推理可能不夠好，但這是一個可以在 E2 測的變數。

**與其他問題的關係**　Q0 選 A（效能）時需要角色 A 或 C；選 B（知識的價值）時各角色都可以；選 C（可解釋）時需要角色 A 或 E。

**建議**　主要角色選 C（規劃者）或 B（仲裁者），配合 Q2 的決定；同時做 D 當次要研究。

- 理由：每步都呼叫 LLM（A）成本高，而且多數步驟的選擇影響不大（待 C3 確認）。B、C 把 LLM 用在真正需要判斷的地方。
- D 的成本低、可以和人工手冊直接比較，很適合當「資料轉成知識」的第二條證據線。

**會推翻建議的證據**　C3 顯示每一步的影響力差不多，沒有明顯的高影響階段。這時 B 的「只在困難時呼叫」沒有依據，回到 A 或 C。

**最晚何時決定**　D 組開工前。

**需要你回答**　LLM 必須是建牆時的決策者嗎？還是「LLM 參與了決策知識的產生」也算達到研究目的？

**已決定**　線上與離線兩條線都做：線上 LLM 當規劃者或仲裁者（依 Q2），離線由 LLM 讀分析結果寫成手冊，與人工手冊比較。

## Q4 保留集與驗證協定

**決定什麼**　哪些種子、哪些場景要完全保留到最後評估才用，以及怎麼防止反覆調整 prompt 而過度配合資料。

**為什麼影響大**　factorial 跑完後，所有種子都會被分析、拿來調 prompt。如果最後評估也用這些種子，結果一定偏樂觀，而且無法事後補救。**這是唯一必須在 S1 開跑前決定的問題。**

**選項**

| 層級 | 作法 | 驗證的是什麼 | 成本 |
| --- | --- | --- | --- |
| 種子保留 | 指定 5 個種子，factorial 與分析都不用 | 在同場景、新石頭組合上是否成立 | 保留種子要另外跑基準牆（S4d） |
| 場景保留 | 指定一個場景，從頭到尾不分析，只在最後評估 | 知識能不能用到沒看過的場景 | 該場景要另外跑基準牆 |
| 開發與測試分開 | 調 prompt 只用部分 factorial 種子（例如 3 個），用另外 2 個做內部測試 | 防止 E1、E2 反覆調整後過度配合 | 開發資料變少 |
| 事先登記 | 檢定與比較寫進計畫並 commit，之後才看資料 | 防止事後挑結果 | 幾乎沒有 |

**保留場景的候選**

| 場景 | 特色 | 適合度 |
| --- | --- | --- |
| `RB`（rubble） | 不在目前 5 個場景內，未分析過 | 高。可以測試對新石頭類型的推廣 |
| `FF_D20` | 石頭多（約 100 塊），牆較大 | 中。成本高，但可以測試規模推廣 |
| 5 個場景之一（例如 `AL_IR`） | 已在 121 面中 | 低。已經看過這個場景的資料 |
| `BR`（磚） | 磚全部相同，順序不影響結果 | 不適用 |

**建議**

- 保留種子 610、616、632、703、760（已寫在計畫的 S0）。
- 保留場景 `RB`：S4d 時一起建基準牆，E3 才第一次分析。
- factorial 的 5 個種子中，prompt 開發只用 3 個（313、484、717），720、761 留作 E1 的內部測試。B 組與 C 組的統計分析仍使用全部 5 個種子。
- 事先登記：B2、C2、C4 的檢定在看到 S2 的資料之前寫進計畫。

**會推翻建議的證據**　`RB` 的建牆時間太長或資料有問題時，改用 `FF_D20`，或放棄場景保留，只宣稱「同場景內成立」。

**最晚何時決定**　S1 開跑前（至少要確定保留種子）。

## Q5 統計單位與去重

**決定什麼**　每一種分析把什麼當作一個樣本、什麼情況要去重。

**為什麼影響大**　去不去重，結論可以差很多。舊資料中，不去重時 LLC 對 `F_LR` 的一致率會從 22/34 膨脹到 84%。但反過來，在某些分析裡去重會讓估計產生偏誤。

**問題在哪**　factorial 計畫寫著「統計前一定要去重」，但不同的問題需要不同的單位：

| 分析 | 問的是 | 樣本 | 去重 | 理由 |
| --- | --- | --- | --- | --- |
| B 組：順序的效果 | 用這種順序，結果怎樣 | 每種順序的那一面牆 | **不去重** | 每種順序是一個處理。兩種順序蓋出同一面牆，就是兩個處理各自的有效結果。去重的話，某面牆只能算給一種順序，反而扭曲比較 |
| B 組的推論 | 結論能不能推到新種子 | 種子 | — | 同種子的 120 面牆共用前段，彼此不獨立。信賴區間與 p 值以種子為單位（例如以種子為區組的置換檢定，或把種子當隨機效果） |
| C 組：分支點 | 當下這樣選，最後比較好嗎 | 不重複的分支點 | **一定去重** | 同一個分支點被很多面牆經過，不去重會重複計算 |
| C 組的推論 | — | 種子 × 場景 | — | 同一棵樹裡的分支點不獨立 |
| A4：牆的分布 | 這個場景的牆長什麼樣 | 不重複的牆 | 去重 | 描述的是「出現過哪些牆」 |
| B3：上限 | 最好能到多好 | 每個種子 × 場景 | 不影響 | 取最大值，去不去重相同 |

**另一個要注意的問題**　5 個種子時，B 組的推論自由度很小。以種子為單位的檢定只有 5 個區組，要依賴場景之間的合併，因此「各場景方向一致」這個假設很重要（B5 會檢查）。

**建議**　採用上表，並把「依分析決定單位」寫進計畫，同時修改 factorial 計畫裡「統計前一定要去重」這句，改成指向這張表。

**最晚何時決定**　開始寫 A1、A3 的工具前，因為總表要同時保留「每面牆」與「去重後」兩種檢視。

**需要你回答**　同意 B 組不去重嗎？如果你或指導教授偏好一律去重，B 組要改成以「不重複的牆」為單位，並說明哪種順序對應哪面牆。

## Q6 標籤的定義：「這個選擇最後比較好」是什麼意思

**決定什麼**　在一個分支點，用什麼數字代表「選這個子節點的最終結果」。

**為什麼影響大**　C4（h 篩選）、C5（排序模型）、C6（可信度表）、E1（離線評估）全部依賴這個標籤。標籤的定義錯了，所有預測力的結論都會錯。

**問題在哪**　一個子節點底下的葉子，在分歧之後仍走各自的順序。所以子節點的「結果」同時混入了這一步的選擇，以及之後的政策。surface-fit 計畫也提過：分歧後兩面牆的政策可能不同，所以一致率不是因果。

**選項**

| 標籤 | 定義 | 優點 | 缺點 |
| --- | --- | --- | --- |
| A 子樹平均 | 子節點底下所有不重複葉子的平均 | 不必新跑；用到全部資料 | 混入之後的政策差異；葉子少時不穩 |
| B 依順序數加權平均 | 葉子依走到它的順序數加權 | 反映「隨機挑一種順序繼續建」的期望值 | 同 A |
| C 子樹最佳 | 子節點底下最好的葉子 | 對應「之後都做對」的潛力 | 葉子多的子節點佔便宜；過度樂觀 |
| D 固定政策續建 | 從子節點強制用 Paper 建完 | 乾淨的因果標籤；對應 rollout 方法的價值定義 | 要新跑模擬（類似 S4c）；只有 Paper 自己走過的路徑上本來就有這種葉子 |
| E 多次續建 | 從子節點用隨機控制器建完 m 次 | 估計期望值與變異，能分出「混沌」與「結構」 | 成本是 D 的 m 倍 |

**D 的成本估計**　要等 A3 數出每棵樹有多少分支點、每個分支點有幾個子節點、平均剩幾塊石頭才能算。以第二顆起每顆約 0.35 秒估計，一條續建約 5–15 秒加上開機時間。分支點數量是主要的未知數。

**與其他問題的關係**

- Q1 決定標籤用哪個指標。
- 選 D 或 E 時，S4 要加一個「續建」選項，而且可能比 factorial 本身還貴。
- E 能回答 surface-fit 計畫留下的問題：「單次分歧的差異有多少是真實結構、多少是混沌」。

**建議**

- 主要用 A 篩選（C4 初篩、C6）。
- 通過初篩的 h 與模型，再抽樣 D 做因果確認（即 S4c）。
- 在少量分支點做 E，量出混沌的大小。如果混沌很大，代表早期決策根本無法預測，LLM 只在尾盤介入（對應 Q2、Q3）。

**會推翻建議的證據**　A 與 D 的方向經常不一致。這時 A 不可靠，主要標籤要改用 D，S4 的預算也要大幅提高。

**最晚何時決定**　C 組分析之前（S2 結束前）。D、E 要不要跑，在 G2 決定。

**需要你回答**　願意為了乾淨的因果標籤多跑模擬嗎？大約的上限是多少小時？

## Q7 資訊邊界：LLM 可以知道什麼

**決定什麼**　控制器在決策時能看到哪些資訊。

**為什麼影響大**　現行控制器看不到「還沒抽到的石頭」（`order_controller.py` 開頭的 Information boundary），觀測第 2 版只給已抽過的石頭尺寸與「從沒抽到的數量」。但 surface-fit 的 H3、H4 需要全部剩餘石頭的形狀，H2b 的參考寬度也是由剩餘石頭算出來的。**如果不放寬邊界，C4 選出的 h 根本不能給 LLM 用。**

**現有證據**

- surface-fit 計畫寫「18 塊石頭都已知，每步抽 7 塊只影響當步能選誰」。也就是說，那份計畫已經假設 h 能看到全部剩餘石頭。
- 現實中，砌牆工人看得到整堆石頭。看不到的是「下一次會抽到哪幾塊」，也就是 RNG。

**選項**

| 邊界 | 能看到 | 合理性 | 影響 |
| --- | --- | --- | --- |
| A 現行 | 當下抽到的石頭、過去抽過的石頭尺寸 | 最嚴格 | H3、H4 不能用；H2b 只能用已看過的石頭近似 |
| B 加上全部剩餘石頭的形狀 | A 加上每塊剩餘石頭的像素或外框 | 符合現實 | 觀測要新增欄位；控制器要載入石頭形狀（surface-fit 計畫已提到） |
| C 加上離線統計 | B 加上從其他種子得到的經驗（手冊、模型、檢索） | 等於有經驗的工人 | 必須確定沒有用到保留種子（Q4） |
| D 加上未來抽樣 | C 加上 RNG 會抽到什麼 | 不合理，是作弊 | 不採用 |

**建議**　採用 C。新增觀測第 3 版，加入全部剩餘石頭的形狀摘要。舊版本保留，讓既有的牆可以重放。在 `order_controller.py` 的 Information boundary 說明中寫清楚：離線知識只來自非保留的種子與場景。

**最晚何時決定**　C4 之前（S2 結束前），因為 C4 篩選的 h 必須是控制器看得到的資訊算得出來的。

**需要你回答**　同意讓控制器看到全部剩餘石頭的形狀嗎？

## Q9 公平比較的預算

**決定什麼**　LLM agent 和基準方法比較時，預算怎麼對齊。

**為什麼影響大**　不對齊預算的比較沒有說服力。舊資料顯示「建 N 面挑最好的」改善很大（Search cost and restart baseline），所以任何方法花的計算量只要比 Paper 多，就要和「用同樣的時間多建幾面再挑」比較。

**兩種預算**

| 預算 | 算法 | 回答什麼問題 |
| --- | --- | --- |
| 姿態評估次數 | 計算量相同（surface-fit 計畫已決定採用） | 演算法本身是否比較聰明 |
| 時間或金錢 | 牆鐘時間或 API 費用相同 | 實際使用時是否划算 |

LLM 的成本主要是 API 呼叫，不是姿態評估。用第一種預算，LLM 幾乎免費；用第二種預算，LLM 的一次呼叫可能等於建好幾面牆的時間。

**多次重啟對照的問題**　「建 N 面挑最好的」需要在建完後評估，等於使用了最終評估，而 LLM agent 看不到。兩者要分開報告：多次重啟是「花更多計算的上限」，不是同條件的對手。

**建議**

- 主要比較用姿態評估次數對齊，同時另外記錄時間與 API 費用。
- 多次重啟當作參考上限：N 取「與 LLM agent 花費相同牆鐘時間」所對應的面數。
- E4 報告每面牆的費用。

**最晚何時決定**　E 組開工前。

**需要你回答**　研究偏重演算法的比較，還是實用性的比較？

## Q10 LLM 供應商、模型與重現性

**決定什麼**　用哪個模型、怎麼控制費用、怎麼讓結果可以重現。

**現有基礎**

- 目前的實牆用 OpenAI（`research/llm_walls/gpt_wall.py`），有花費帳本與安全閘。
- 控制器會把每次對話完整記錄下來，`ReplayLLM` 可以用紀錄重放。
- 付費呼叫需要 `STONEPACKING_ALLOW_PAID_API=1` 與 `--confirm-paid`。

**要決定的事**

| 項目 | 選項 | 考量 |
| --- | --- | --- |
| 模型 | 1 個主要模型，或比較 2–3 個 | 比較多個模型可以看「知識」的效果是否跨模型成立，但費用加倍 |
| 推理強度 | 高推理或低推理 | 高推理比較準，但慢又貴；如果只在尾盤呼叫，比較負擔得起 |
| 溫度與重複 | 每個設定跑 1 次或多次 | LLM 即使設定固定也不完全確定，多跑幾次才能估計變異 |
| 預算上限 | 每面牆、每個實驗、整個專案 | E1 的離線評估可能要評估幾千個分支點 |
| 多模態 | 是否給牆面圖片（Q3） | 要選支援圖片的模型 |

**建議**　

- 1 個主要模型做全部實驗，再挑 1 個模型只重複 E3 的關鍵比較。
- E1 先用小樣本（例如 200 個分支點）估計費用再擴大。
- 每個設定在 E3 至少重複 2 次，估計 LLM 自己的變異。

**最晚何時決定**　E 組開工前。
