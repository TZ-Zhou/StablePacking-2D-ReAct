# 整面牆的簡單規則：把 check_after 工具的功勞和 LLM 的功勞分開

LLM 整面牆直接選（`docs/plans/llm-whole-wall-pick.md`、`llm-whole-wall-confirm.md`）在 10 面 `TH` 牆中有 7 面不輸 Wang 的 Paper 牆。LLM 那邊同時有兩樣 Wang 沒有的東西：`check_after` 工具（知道放下某個候選之後，其他被抽到的石頭下一步還放不放得下），和 LLM 自己的選擇。7/10 是哪一樣的功勞，現有的牆分不出來。

這一批不用 LLM、不花錢，在同樣的 10 面牆上加蓋三種簡單規則的整面牆，用同樣的「不輸 Wang」標準算，和 LLM 的 7/10 比。

本文在蓋任何一面牆之前 commit；之後要改，另開 commit，報告時列出差異。

## 三種規則

共同的部分和 LLM 的整面牆完全一樣：同一個種子、同樣的石頭、基底排序是 Paper（`30214`）；每一步的候選就是 Wang 的抽樣在這一步抽出的那一批；**決策點**是每一次有 2 個以上可行候選的選擇（只有 0 或 1 個可行候選時照 cascade）；`check_after` 的表就是 LLM 的工具讀的那一張（`build_wall.py` 在每個決策點算，不動亂數）。

**安全候選**的定義照 `docs/plans/llm-endgame-lookahead.md`：可行，而且它在 `check_after` 表的那一列沒有 0，也就是放下它之後，這一步其他被抽到的石頭在下一步都至少還有一個可行姿勢。一個決策點沒有任何安全候選時，規則把全部可行候選都當成可選。

| 規則 | 用工具 | 怎麼選 |
|---|---|---|
| `wang_safe`（Wang + check_after） | 是 | Wang 的 cascade 選的候選如果安全（或這一步沒有安全候選），就選它；不安全時，只在安全候選中重跑一次 Paper 排序的 cascade（各層的平均值只用安全候選算），選它的結果 |
| `pick_safe` | 是 | 安全候選中 LLC 最高的；同分取編號最小的。就是 `llm-endgame-lookahead.md` 的假 LLM `pick_safe`，走 pick 控制器和 `check_after` 工具，設定同 LLM 的整面牆（`whole_wall`、`max_tool_calls` 4、`max_decisions` 25），不連網路 |
| `borda` | 否 | 全部可行候選中，五個分數的名次總和最高的（同分取編號最小的）；`research/controller/endgame.py` 的 `borda`，改成每個決策點都選 |

各個比較回答什麼：

- `wang_safe` 對 Wang：只加工具、選法不變，牆會不會變、變好還是變壞。
- LLM 對 `wang_safe`：有了工具之後，LLM 的選擇有沒有再多出什麼。
- `pick_safe`：工具加上只看一個分數的規則，沒有 Wang 的 cascade 也沒有 LLM。
- `borda`：沒有工具也沒有 LLM，五個分數一樣重。

三種規則都是確定的（沒有亂數、沒有 LLM），每面牆只蓋一次，重蓋會得到同一面牆。

## 判定規則（只判定一次）

每面規則牆「不輸 Wang」的定義和 LLM 的牆相同，三項都要成立：

- 這面牆走完，而且每個決策點都是規則選的（`PROCESS_PASS`，控制器檢查 PASS；`pick_safe` 沒有退回 cascade）；
- 規則的牆四項平均 z **不低於** Wang 的牆（相等也算）；
- 規則放下的石頭數**不少於** Wang 的牆。

每種規則數出 10 面中不輸 Wang 的面數，和 LLM 的 7 面比。判讀先講定：

| 規則不輸 Wang 的面數 | 判讀 |
|---|---|
| 7 以上 | 這個規則不用 LLM 就達到 LLM 的面數 |
| 5 或 6 | 分不開：和 LLM 只差 1、2 面，10 面牆看不出差別 |
| 4 以下 | LLM 比這個規則多 3 面以上 |

工具和 LLM 的功勞用 `wang_safe` 那一列判讀：

- 7 以上：「7/10 用 Wang 的選法加 `check_after` 就做得到，不能算 LLM 選擇的功勞」；
- 4 以下：「Wang 的選法加 `check_after` 做不到 LLM 的面數，LLM 的選擇有超出工具的貢獻」；
- 5 或 6：「分不開」。

30 面牆沒有全部走完、或下面的檢查沒有全過，就不判定，只報告。

**這個標準的限制，先講清楚**

- 和 Wang 完全相同的牆也算不輸 Wang（LLM 的牆適用同一條）。`wang_safe` 只在 cascade 選到不安全候選時才改選，改選次數少的話牆會和 Wang 的相同，面數自然高；那代表「工具很少改變 Wang 的選擇」，不代表「工具有幫助」。所以報告一定同時列出每面牆有幾個決策選得和 cascade 不同、有幾面牆和 Wang 的牆完全相同，以及「不輸 Wang 而且和 Wang 的牆不同」的面數（LLM 是 7 面）。
- 10 面牆很少：隨便換一個過濾排序，10 面中至少 6 面不輸 Wang 的機率是 0.24，至少 7 面是 0.07（`llm-whole-wall-confirm.md`）。差 1、2 面不是證據。
- LLM 的牆每面只蓋過一次，同樣的牆重跑 LLM 可能選得不同；規則的牆是確定的。

**另外報告**（不進判定）

- LLM 和每種規則在同一個區塊直接比：LLM 的牆不輸規則的牆（平均 z 不低於、石頭不少於）的面數，反過來的面數，以及 10 面的平均 z 差（LLM − 規則）。
- 每種規則每面牆：規則 − Wang 的四項 z 差與平均 z 差、放下的石頭數、在該區塊 120 個排序中的百分位。
- 決策點數、選得和 cascade 不同的決策數；用工具的兩種規則另外列出「同時有安全和不安全候選」的決策點數（工具能起作用的地方）和選到不安全候選的次數。

## 檢查（判定之前全部要過）

1. 單元測試：`wang_safe` 的選法（cascade 選的安全就不變；不安全時等於只給安全候選的 cascade；沒有安全候選時不變）；整面牆選項讓庫存不空的選擇也成為決策點；沒有這個選項的 spec 和紀錄不變；判定規則的測試。
2. 舊牆不變：重蓋 factorial、lookahead-arena 各 1 面，和原本完全相同；已有的 47 面付費牆，控制器檢查仍是 PASS。
3. 30 面牆都是 `PROCESS_PASS`，trace 檢查和控制器檢查 PASS（規則在 trace 上重新執行的結果等於紀錄；每一步 `check_after` 的那一列和下一步實際可行數相符）。
4. 同樣的石頭：每面牆第一步的候選（石頭 id 和分數）與 Wang 的牆第一步完全相同。

## 實作

- `research/controller/endgame.py`：spec 加選填的 `whole: true`（每個有 2 個以上可行候選的選擇都選，不只庫存空了以後），加模式 `cascade_safe`（上表的 `wang_safe`）。沒有 `whole` 的 spec 不變，舊牆的紀錄照舊重播。
- 批次的排序寫法加 `30214+whole_<模式>`（`research/walls/batch_plan.py`）；每個區塊一個批次 `whole-rules-s<種子>-<牆>`，共 10 個批次、各 3 面。
- 判讀 `research/analysis/whole_wall_rules.py`。
- 不改 `build_wall.py`、不改 pick 控制器、不改提示。

## 花費

不呼叫任何 API、不設付費開關；`pick_safe` 的假 LLM 在本機同一個程序裡回答。只花本機時間，估計 30 面牆一小時以內。

## 限制

只有 `TH` 兩種牆、10 個區塊。安全候選用的是既有的定義（表裡有 0 就不安全）；更細的用法（例如選讓最少石頭變 0 的候選）沒有測。規則贏過或輸給 LLM，都只是這 10 面牆上的描述。
