# 計畫：每顆石頭放置 < 2 秒，目標 0.5 秒

把 run batch 的建牆邏輯加速，**計算結果完全不變**。

硬目標（第二顆起每顆 < 2 秒）已達成；努力目標（每顆 < 0.5 秒）只有部分牆達成。工作在分支 `pref/speed-up`，未合併 `main`，合併時機由使用者決定。

## 目標定義

| 項目 | 內容 |
| --- | --- |
| 硬目標 | 8 種牆的每一顆放置，第二顆起**最大值** < 2 秒 |
| 努力目標 | 第二顆起每一顆 < 0.5 秒 |
| 不計入 | 第一顆放置（含 worker 啟動）、開機（載入石頭、形狀因子）、牆蓋完後的收尾搜尋與評估 |
| 不變條件 | 同場景、政策、順序、種子的牆，`check_run.compare_runs` 零差異：決策、篩選值、變換、`commits.jsonl`、每個事件 npz、`base.pkl`。`mechanism.csv` 相對差 < 1e-12 |

一顆的時間 = 這顆 `placed` 提交的時刻減上一顆 `placed` 提交的時刻，中間的 probe 與 `no_placement` 重抽都算在這顆內。來源是 `events.jsonl` 的 `step_commit`，由 `wall_metrics.stone_seconds` 計算。

### 量過但不採用

| 想法 | 原因 |
| --- | --- |
| 大石頭優先排程 | 成對量 `AL_IR`：1.511 → 1.498 秒，在雜訊內（同一份程式兩次差 0.37 秒） |
| kine 為 0 時省第二個 LP | 只有 13–16% 的 pose 符合，省幅 < 2% |
| 石頭疊成多通道一次卷積，或用 FFT | 分數是浮點累加，捨入不同，平手順序會變 |
| 只算頂層固定列帶 | 有 pose 選在帶外，會漏；改用實際候選點外框 |
| 少評估 pose、略過 probe、只算一側、放寬 LP 精度 | 改變結果 |
| numba、Cython | 不在凍結環境內，決定不改環境 |
| 綁定 CPU（affinity 0x5555） | 量測無改善 |
| 控制器的牆改用非同步寫出 | 沒量。`run_wall` 規定控制器的牆同步寫出，`run_wall.check_commits` 又要求被殺的牆是寫出順序的前綴，改了要先確認兩者仍成立 |

## 剩餘

- `AL_IR` 是唯一一種多數石頭仍超過 0.5 秒的牆。每顆平均 160 個 pose，單行程每個 pose 約 17 毫秒，其中 `solve_force_rigid` 約佔 42%（兩次 LP，cProfile 量），結果不變的前提下不能少解。量過 8 workers 同跑時，每個 pose 的時間約為單行程的 2 倍；原因沒有拆開量，綁定實體核心沒有幫助。
- 主行程序列成本每次抽樣每側約 86 毫秒（`AL_IR`，cProfile）：共享區塊 28、`rotated_by_90` 14、`deepcopy` 11、trace 8。
- 剩餘手段的估計省幅都不到 5%（D2 停止條件成立）：`non_overlap` 列裁切約 3%，`rotated_by_90` 裁切約 1.5%，共享區塊去重最多約 5%（要改傳輸格式）。
- 批次層 C1–C3 未做（`docs/TODO.md`），不影響每顆指標。
- `AL_IR` 最慢的石頭離 2 秒只有 5–10%（固定順序 1.81–1.84、`random` 1.91），批次有 24 面 `AL_IR`，換機器或背景有負載就可能超過。
- 沒驗證：`--modes fresh` 整面牆（`AL_PR` `paper` 跑到逾時，已寫出部分與金牌相同）、LLM 與 `rule` 控制器、其他 worker 數、`--no-trace`、其他機器；批次 121 案例實際建了 7 個，只有案例 23 與基準比過。
- `prefill_regions` 算出的地面面積比 regionprops 少 4 像素（場景把地面邊界改寫成 255），形心相同；LP 的地面列是自由的，結果不受影響，`region_memo` 的註解要改。
- `verify_speedup` 比封存牆時，`bricks code_original` 的 104 筆差異會讓 exit code 變 1，基準牆也一樣。

## 決定

| 編號 | 問題 | 決定 |
| --- | --- | --- |
| D1 | 核准本計畫 | 核准 |
| D2 | 0.5 秒何時停止追 | 所有牆 < 2 秒後，下一項手段估計省幅 < 5% 就停，其餘牆記錄實測值 |
| D3 | 需要改環境時 | 不改環境 |
| D4 | 合併到 `main` 的時機 | 使用者決定 |

## 重新驗證

金牌牆在 `speedup-baseline` worktree（`59ae057`）的 `runs/speedup/golden`。

```bash
python -B -m research.runner.verify_speedup <label> --modes persistent --workers 8 --timeout 3600 --golden <金牌牆絕對路徑>
```

要設 `PYTHONPATH` 指向要測的 checkout，否則 `Stonepacker2D` 會 import 到主工作樹（可編輯安裝）。
