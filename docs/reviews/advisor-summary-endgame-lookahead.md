# 給教授的進度摘要：濾波器順序與 LLM 殘局選擇

數字與表格都在 [`research/findings.md`](../../research/findings.md)，本文只寫結論，並註明出自哪一節。

## 名詞

| 名詞 | 意思 |
| --- | --- |
| 濾波器順序 | Wang 每一步用 5 個濾波器依序篩候選：0 NHR、1 GDS、2 IWR、3 LLC、4 LFR。Paper 的順序是 3,0,2,1,4 |
| 四項指標 | `F_SF`、`F_AV`、`F_LR` 越大越好，`F_AH` 越小越好；比較時換成 z，正數代表較好 |
| cascade | Wang 原本的逐層篩選，即不加任何控制的牆 |
| 殘局 | `TH_T80` 剩 7 塊石頭以後的 7 步。這時每一步所有剩下的石頭都可以選，沒有抽樣，所以從同一個狀態出發的不同方法可以直接比較 |
| pick_safe | 不用 LLM 的規則：拿 LLM 同樣的可行性表，在安全的候選裡選 LLC 最高的，並列時取第一個 |

## 結論

| 主題 | 結論 | findings.md 的章節 |
| --- | --- | --- |
| 3,000 面牆：Paper 和其他順序比 | Paper 只在 `F_LR` 常贏過中位數，其他指標有好有壞；最好的順序只和運氣預期一樣好，換種子幾乎不會重複 | Factorial → B3 |
| 這一步的分數能否預測最後的牆 | 24 組裡只有 LLC→`F_LR` 和 NHR→`F_AH` 顯著，效果都小 | Factorial → C2 |
| 表面形狀啟發式 | 全部不通過，還低於最簡單的基準 | Factorial → C4 |
| 殘局有沒有改進空間 | 有：在部分狀態中，有其他結尾比 cascade 好 | Endgame → Free arena |
| LLM 直接選（step 3） | 沒有證明殘局貢獻，還掉了石頭；原因是選了會讓另一塊石頭沒有位置的候選 | Endgame → step 3 |
| LLM 加 `check_after` 可行性查詢 | 判定 go，不再掉石頭；但剛好過門檻 | Endgame → check_after |
| LLM 對 pick_safe（探索性） | 平均比 pick_safe 差，9 個狀態裡贏 4 個 | Endgame → LLM against pick_safe |

**為什麼改做殘局**：重新排序濾波器能改的空間很小，也找不到能預測最後結果的簡單分數。所以改讓 LLM 直接選放置，並先從沒有抽樣雜訊的殘局開始。

## 新發現：LLM 輸在哪裡

出處：findings.md 的「LLM against pick_safe」。

- **輸的狀態都輸在 `F_LR`**：LLM 輸給 pick_safe 的 5 個狀態，`F_LR` 全部比較低，而且差距大。
- **為了 NHR 放棄 LLC**：提示要 LLM 比較全部五個分數，也沒說 LLC 就是 `F_LR` 的每一步版本（兩者的定義寫得幾乎一樣，但沒有點明）。
  - 用了可行性查詢的 53 次決策中，有 13 次 LLM 沒選 LLC 最高的安全候選。
  - 全部 14 次這樣的決策裡，有 11 次 LLM 選的候選 NHR 比所有 LLC 最高的候選都高。
- **贏的時候靠其他分數**：大多數決策都有好幾個候選並列最高 LLC。pick_safe 遇到並列只取第一個，LLM 則用其他分數在並列中挑。
  - LLM 贏最多的 484/02413，每一次決策都有 2–9 個安全候選並列最高 LLC。
  - LLM 幾乎都選在並列之內，而且多半和 pick_safe 選的不同。
  - 結果主要贏在 `F_AV` 和 `F_AH`。

**可能的下一步（給 LLM 加知識）**：在提示中說明「LLC 是 `F_LR` 的每一步版本：先選 LLC 最高的安全候選，並列時再用其他分數」。這等於讓 LLM 做 pick_safe 做的事，再加上 pick_safe 沒有的、處理並列的判斷。要做的話，判定規則會在建牆前先 commit，並換一組新的狀態。

## 要注意的地方

- go 只是剛好過門檻，其中一個狀態只贏 cascade 0.003。
- 進步主要來自可行性表：pick_safe 不用 LLM，也不掉石頭，平均還比 LLM 好。
- step 3 和修法 2 用的是不同的 9 個狀態，兩者的數字不能直接相減比較。
- 目前只有殘局 7 步、只有 `TH_T80`、只有 3 個開發種子。事先登記的 B2、B4 還沒跑。
